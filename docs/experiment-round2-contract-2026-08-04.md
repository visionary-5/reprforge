# ReprForge 第二轮实验契约

日期：2026-08-04。所有阈值在查看第二轮结果前冻结。两个分支都只使用现有分数面做 CPU 回放，不启动新的视觉编码。

## `exp/aging-aware-frontier`

问题：能否在 W=32 的因果可见窗口内，用软公平机制保留前沿调度效率，同时显著减少旧请求被反复绕过？

候选方法至少包括年龄连续加分、软绕过预算和双队列服务配额。调度器只能观察到达时间、候选页面集合、已经常驻/正在构建的页面和历史调度状态。

选择规则：允许在 HR 或合成轨迹上选择超参数；Finance 参数必须完全冻结。

GO 门槛为 HR/Finance × burst/Poisson 四个设置同时满足：

- W=32 至少保留完整可见队列 50% 的平均完成工作收益；
- 质量--工作 AUC 不低于 FIFO；
- 饥饿请求比例不超过 5%；
- 最终页面并集和最终检索质量与其他调度一致。

必须同时报告 P50/P95/max 等待、最大 younger-bypass、硬公平规则和无公平规则，不能只报告均值。

## `exp/value-aware-frontier`

问题：能否在保持页面复用收益的同时，用廉价侧的不确定性信号更早完成可能带来正向证据修订的查询？

允许信号包括 BM25 候选分数的边界间隔、熵、候选集合重叠、已常驻覆盖率和页面跨查询复用。禁止使用 qrel、答案、视觉分数或真实查询质量增益参与调度。

选择规则：只能在 HR 上选择方法和超参数；Finance 与 IRPapers 是冻结迁移集。

GO 门槛为两个迁移集同时满足：

- 质量--工作 AUC 不低于静态热门度；
- 平均完成工作量低于静态热门度；
- 最终页面并集和最终检索质量完全相同。

必须消融“仅复用”“仅廉价价值”和联合目标，避免把收益归因于未经验证的复杂打分。

## GPU 解锁条件

只有任一分支通过其完整 GO 门槛，才解锁新的 A100 真实运行。GPU 实验不再用于选参数，只验证冻结策略的首批完成时间、平均/P95 查询完成时间、总构建时间和峰值显存。
