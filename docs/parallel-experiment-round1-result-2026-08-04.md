# ReprForge 第一轮并行实验结论

日期：2026-08-04。基线分支：`research/anytime-index-base`。

## 一句话结论

现有数据已经把工作从“一个工程解耦方案”推进成了一个可以论证的研究问题：
**当昂贵的多模态表示只能逐步构建时，如何根据查询产生的异构候选依赖，决定先构建哪些页面、先完成哪些查询，使有限构建预算更早转化为可用检索质量。**

第一轮证据支持把“常驻前沿调度”保留为主方法核心，但不支持把当前算法直接视为完成版。主要缺口已经从“收益是否只是热门度或重叠造成”收敛为两个具体问题：

1. 有限等待窗口下的效率与公平性；
2. 页面复用价值与证据质量价值并不总是一致。

全部分支使用冻结分数面或现有真实运行产物；调度器不可见相关性标签。各调度最终使用相同页面并集并达到相同最终检索质量。第一轮没有启动新的 GPU 编码任务。

## 现在可以讲什么

可以讲的核心事实是：

- 廉价文本定位器为每个查询给出候选页面集合；不同查询的集合大小、重叠和潜在质量收益并不相同，因此形成“异构索引依赖”；
- 多模态页面表示是昂贵且可复用的构建单元；一个页面构建后可以同时推进多个查询；
- ReprForge 根据已经常驻的页面、当前批次将新增的页面以及后续复用机会，选择更接近完成的查询群；
- 相比 FIFO，候选查询能更早完成；相比只看热门度、静态重叠或剩余大小的算法，动态常驻状态仍有独立价值；
- 最终构建的页面集合和最终质量不变，改变的是“质量在构建过程中何时变得可用”。

不应讲成：

- 前沿算法在所有指标和所有负载下全面最优；
- W=16 或 W=32 已足以支持任意在线交互流量；
- 页面复用最多就一定能最早带来正确答案；
- 当前安全发布器已经解决多模态修订伤害。

## 对“证据质量”的操作化定义

“证据质量”不能只写成直觉名词。当前实验里至少要拆成三层：

1. **候选覆盖**：廉价定位器是否把相关页面放进候选集合。例如 IRPapers 的 gold-in-K 或 Recall@K。
2. **排序质量**：构建多模态表示后，相关页面是否进入最终前列。当前用 nDCG@10 或 Recall@5。
3. **过程质量**：在固定构建预算下，已经完成的查询带来的平均排序质量，即质量--工作量曲线及其面积。它回答“同样构建 500 个页面，哪个方法已经交付了更多有效证据”。

HR 在主设置上静态热门度的质量--工作 AUC 高于前沿；IRPapers 也有相同现象。这说明调度目标不能只最小化完成页面数，还需要一个不看标签的“预期证据价值”信号。

## 下一轮方法方向

### 方向 A：带软公平约束的前沿调度

当前硬规则一旦老请求被绕过 W 次就强制执行，能消除饥饿，却损失大半效率。下一轮应比较：

- 年龄加分：等待越久，优先级连续提高；
- 软绕过预算：保留少量高复用选择，但逐渐限制继续绕过；
- 双队列配额：大多数批次优化复用，固定少量批次服务最老请求。

门槛冻结为：W32 在 HR 和 Finance 的 burst/Poisson 四种设置都保留至少 50% 完整队列收益，质量--工作 AUC 不低于 FIFO，同时饥饿比例降至 5% 以下。参数只在 HR 或合成轨迹上选择，再原样迁移到 Finance。

### 方向 B：价值感知的前沿调度

IRPapers 和 HR 表明，工作最省的查询批次不一定具有最大的正向质量增益。不能用 qrel 或真实增益直接排序，但可以尝试只由廉价侧产生的可部署信号：

- BM25 候选边界间隔和分数熵；
- 查询候选与已有多模态页面的覆盖程度；
- 不同廉价定位器之间的一致性/分歧；
- 候选页面的跨查询复用与查询不确定性的联合分数。

目标是找到“每新增一个页面，预期能完成多少查询、释放多少质量”的双目标前沿。先做严格跨数据集迁移：HR 选择规则，Finance 和 IRPapers 只评估；若反向选择也一致，再考虑写成学习模型。

## GPU 决策

现在不应立刻扩大全量 A100 运行。已有冻结分数面足以筛选调度设计，且新算法不会改变视觉编码本身。下一次真实 GPU 实验应满足至少一个条件：

1. 软公平 W32 同时通过效率和饥饿门槛；
2. 价值感知规则在 Finance 与 IRPapers 的质量--工作 AUC 都优于静态热门度，同时保持前沿的完成工作优势。

通过后再在 A100 上测真实首批完成时间、P50/P95 查询完成时间、总构建时间和显存峰值。这样 GPU 数据验证的是已经冻结的方法，而不是替 CPU 回放搜索参数。

## 当前论文定位

现阶段更稳的论文表达不是“我们把索引和查询解耦”，而是：

> 多模态 RAG 的索引并非必须一次性完整构建。查询先暴露一个具有共享结构的候选依赖图；系统可以把昂贵表示编译成一个随工作预算逐步可用的索引。ReprForge 将候选定位、表示构建和原子发布组织为可验证的过程，并用常驻前沿调度把重复构建工作转化为更早的查询完成和检索质量。

其中“解耦”是使问题成立的系统设计，“异构候选依赖下的渐进式索引编译与调度”才是需要实验支撑的研究贡献。
