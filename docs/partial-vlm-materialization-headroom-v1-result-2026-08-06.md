# 部分 VLM 索引物化 headroom v1：选择空间存在，方法尚未成立

日期：2026-08-06  
协议提交：`f377642`  
判定：**oracle headroom GO；当前廉价选择策略 NO-GO**

## 这轮回答了什么

v1 将“选哪些页面”和“部分视觉索引如何校准融合”拆开。页面一旦被选择，oracle
评测保留它在完整视觉索引中的全局名次或完整语料分数标定；这些信息在实际系统中不可得，
只用于判断页面选择空间是否存在。朴素子索引 RRF/z-score 继续保留，用于度量部署时的
融合缺口。

| 领域 | Text nDCG@10 | Full RRF hybrid | Full - Text | 初始 headroom gate |
|---|---:|---:|---:|---|
| HR | 0.48690 | 0.54612 | +0.05922 | 通过 |
| Finance | 0.53083 | 0.53864 | +0.00782 | 通过，但绝对增益很小 |
| IRPAPERS | 0.67009 | 0.63963 | -0.03046 | 失败；该融合下视觉索引有害 |

两个领域通过预先设定的最低数量 gate，因此“部分持久物化”值得继续验证；这并不代表
ReprForge 方法已经通过。

## 关键结果

在全局 z-score oracle 评测中，标签/排序 oracle 仅选择约 13.5% HR 页面和 3.7%
Finance 页面，就分别达到 0.6178 和 0.6335 nDCG@10，超过完整 z-score hybrid 的
0.5529 和 0.5737。更少页面优于 Full，说明完整视觉索引会引入跨查询噪声，目标函数
不是单调的；也说明真正的问题不仅是“覆盖多少页面”，还包括“哪些视觉表示应进入检索”。

但这个 oracle 使用未来 qrel 和 Full 视觉名次，不能成为方法。当前历史 BM25 候选频率、
文本风险、均匀覆盖及两者组合在 HR/Finance 上均未接近它。例如 40% 页面预算时，历史
频率在全局 z-score 评测中的增益恢复为 HR -5.6%、Finance -58.5%；即使到 60%，也只
恢复约 43.2% 和 39.3%。因此当前瓶颈是**可实现的页面效用信号**，不是页面预算或更复杂
的缓存调度。

IRPAPERS 是有价值的反例：完整 RRF hybrid 比文本低 0.03046，且该 benchmark 的相关
页面几乎不在不同查询之间重复。这里持久物化缺少质量增益和正确证据复用，DVI 式非持久
按需视觉分析更符合工作负载。

## 不能作出的结论

- 不能声称 20%--40% 页面已经恢复 Full 的大部分增益；做到这一点的是未来信息 oracle。
- 不能将超过 Full 的 oracle 数字称为部署质量；它同时利用了选择性去噪和不可得标定。
- 不能把 BM25 Top-20 的重复构建事件直接解释为正确证据复用。
- 不能仅报告“保留 Full 百分比”；必须继续报告绝对增益和 Gain Recovery。

## 下一判定

独立测试仅使用历史反馈的物化策略：历史相关/点击页面频率、视觉风险覆盖和预算填充，
在未来 fold 上评估。若历史反馈仍无法显著缩小 oracle 差距，则当前 benchmark 不足以支撑
可实现的持久物化方法，应停止堆启发式，转向收集有真实访问/反馈 trace 的数据或缩小 claim。
